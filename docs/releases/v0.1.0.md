# Release Notes v0.1.0

Released: 2026-11-11

The first release. A consulting agreement (a proposal or statement of work)
written once in YAML or JSON, checked beyond its schema, and rendered to
Markdown, DOCX, and a PDF the parties sign.

## Highlights

- **One structured agreement.** Parties, background, objectives, scope with
  what is in and **out**, deliverables with acceptance criteria, milestones,
  each side's responsibilities, risks, fees, terms, open questions, and
  signers, every element with a stable ID.
- **Checks that prevent disputes.** 20 lint rules: unique IDs, references that
  resolve, dates in order, fees with a currency, no open questions in an agreed
  version, and warnings for gaps such as nothing out of scope, no client
  responsibilities, or deliverables with no way to accept them.
- **Documents people sign.** Deterministic Markdown, and DOCX and PDF through
  Pandoc, with a document information table, numbered sections, a page footer,
  and a signature block for each signer.
- **Traceable signatures.** Every document prints a content digest of its
  source. The digest ignores status and signing records, so it still matches
  after the agreement is signed.

## New Features

### Model and schema

- The `Agreement` document in `pkg/engagement`, with kinds `proposal` and
  `statement_of_work`, a lifecycle status, and commercial models `pro_bono`,
  `fixed_fee`, `time_and_materials`, and `retainer`.
- The `agreement` JSON Schema, generated from the Go types and embedded in the
  `schema` package for editors and agents. Enumerations come from the Go
  `All…` functions, so the schema and code cannot drift.

### Loading and canonical form

- YAML and JSON input validate and decode identically, with size limits and
  strict decoding: an unknown field is an error.
- `cespec fmt` rewrites a file in canonical form, and `--check` reports files
  that are not.
- `cespec digest` prints the content digest shown on the rendered document.

### Rendering and export

- `cespec render` writes Pandoc-flavored Markdown for conversion, or
  GitHub-flavored Markdown with `--flavor gfm` for reading in a repository.
- `cespec export --out agreement.docx` or `--out agreement.pdf` runs Pandoc.
  Timestamps are pinned to the agreement's date, PDFs use LuaLaTeX, and DOCX
  entry times are normalized, so the same input and toolchain produce the same
  bytes.

### Signing

- The PDF carries a printed signature block for each signer. It works for
  wet ink, PDF fill-and-sign tools, and e-signature services where the sender
  places the fields. Record each signature's `signedDate` and `method` in the
  source afterward.

## Requirements

- Go 1.26 or later to build.
- Pandoc for DOCX and PDF export, and LuaLaTeX for PDF.

## What's Next

- Change orders, acceptance records, and closure reports.
