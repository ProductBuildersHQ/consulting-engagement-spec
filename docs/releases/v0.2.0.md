# Release Notes v0.2.0

Released: 2026-11-21

One agreement, laid out in any organization's form. Programs, firms, and
clients often ask for a work plan in their own sections and order. Write an
**outline** of that form, and `cespec` renders the same agreement in it, with
the same content digest, and adds a **crosswalk** to the full agreement that
shows where each section of the form is answered and what the agreement adds.

The agreement can now also state what the work sets out to test, label its
kickoff and closeout, name each side's point of contact, list the evaluations
and reports owed at the end, and list its signers by capacity, such as a board
representative, before everyone is named.

This release adds to the model and the API and changes no document: a v0.1.0
agreement reads, lints, and renders unchanged.

## Highlights

- **Outlines.** A new document kind that lists sections with their own
  headings and order, each drawn from named blocks of an agreement, such as
  `hypotheses` or `responsibilities.client`.
- **Render in any outline.** `render` and `export` take `--outline`. Built-in
  outlines are `full`, the default and unchanged layout, and `summary`, a
  one-page plan.
- **Crosswalk.** `cespec crosswalk`, and `--crosswalk` on `render` and
  `export` for an appendix to the full agreement: each section of the other
  form, where this document answers it, and what it covers beyond the form.
- **A fuller agreement.** Hypotheses, milestone kinds, points of contact, a
  closeout, and signature lines by capacity, with lint rules for each.

## New Features

### Outlines

```yaml
schemaVersion: "0.1"
kind: outline
id: work-plan
title: Volunteer Program Work Plan
datePrecision: month
sections:
  - heading: Purpose
    from: [summary, objectives]
  - heading: What we will test
    from: [hypotheses, assumptions]
  - heading: What the client provides
    from: [responsibilities.client, governance.contacts.client]
  - heading: Timeline
    from: [phases, milestones]
  - heading: Sign-off
    from: [signatures]
```

- The first block in a section prints under its heading; later blocks get a
  subheading. A section prints only when one of its blocks has content, and
  numbers count only the sections printed.
- Blocks that list people or dates take a filter: a party role
  (`responsibilities.client`, `signatures.consultant`) or a milestone kind
  (`milestones.closeout`).
- An outline can turn off section numbers (`numbered: false`) and the document
  information table (`information: false`), and print dates by month
  (`datePrecision: month`).
- The footer and information table name the layout when it is not the full
  agreement. The content digest is the same in every layout, so any of them
  can be signed.
- Outlines have their own generated, embedded JSON Schema, `outline`, and load,
  validate, and format like agreements: `validate` and `fmt` accept either.
- `cespec outline list` prints the built-in outlines and every block;
  `cespec outline lint` checks outline files for unknown blocks and duplicate
  headings, and with `--agreement` warns about sections that agreement leaves
  empty.

Keep an organization's outline in your own repository, next to the agreement
that uses it.

### Rendering in an outline

```bash
cespec render agreement.yaml --outline summary
cespec export agreement.yaml --outline work-plan.outline.yaml --out work-plan.pdf
```

`--outline full`, or no flag, reproduces the v0.1.0 layout byte for byte.

### The crosswalk

```bash
cespec crosswalk agreement.yaml work-plan.outline.yaml
cespec export agreement.yaml --crosswalk work-plan.outline.yaml --out agreement.pdf
```

The table lists each section of the target outline with the numbered sections
of the agreement that answer it, or "Not addressed", then lists the sections
the target does not ask for. With `--crosswalk`, the full agreement ends with
"Appendix: Correspondence with" the outline's title. `pkg/crosswalk` returns
the same as data.

### New agreement fields

- **`hypotheses`**: a statement, how it is tested, the deliverables that test
  it, and the milestone it is judged at. A Hypotheses section follows the
  objectives.
- **`milestones[].kind`**: `kickoff`, `checkpoint`, `review`, `decision`,
  `final`, or `closeout`. A Kind column appears when any milestone has one.
- **`governance.contacts`**: each party's point of contact and their role,
  printed under Working together.
- **`closeout`**: a summary, evaluations a party gives (subject, method, due
  date), and reports owed to a party, in a Closeout section.
- **`signatures[].capacity`**: the capacity a signer signs in, printed in place
  of their title. A party can have several signature blocks. Capacity is part
  of the content digest.
- **A signer not yet named.** A signature block with a `capacity` may leave out
  `signer`. It prints a blank name line under the capacity, so a form that
  lists its signers by role can be sent before everyone is named.
- **Legal names on signature blocks.** Each block heads with the party's
  `legalName` when one is set, else its `name`.

### New lint rules

| Rule | Severity | Finds |
|------|----------|-------|
| `unknown-reference` | error | a hypothesis, contact, or closeout item naming a deliverable, milestone, party, or person that does not exist |
| `contact-party` | error | a contact whose person is not in the named party |
| `hypothesis-untested` | warning | a hypothesis with no test, deliverable, or milestone |
| `no-kickoff` | warning | milestones with kinds, but no kickoff |
| `no-closeout` | warning | milestones with kinds, but no closeout |
| `no-client-contact` | warning | contacts listed, but none for the client |
| `unnamed-signer` | warning, or error | a signature block with no signer: a warning in a draft; an error with no capacity, a recorded signing, or once agreed |

`no-kickoff` and `no-closeout` apply only once some milestone has a kind, so
v0.1.0 agreements gain no findings.

## Installation

```bash
go install github.com/ProductBuildersHQ/consulting-engagement-spec/cmd/cespec@v0.2.0
```

Go 1.26 or later. Pandoc for DOCX and PDF export, and LuaLaTeX for PDF.

## Upgrading

No document changes: `schemaVersion` stays `"0.1"` and every new field is
optional. Go code compiles unchanged; the API changes are additions.

- `signer` is no longer required in the schema; lint's `unnamed-signer` rule
  takes its place.
- A party with a `legalName` now heads its signature block with that name.

- `schema.Names()` now returns `agreement` and `outline`.
- Indirect dependencies are updated.

## Known Limitations

- **The crosswalk matches by block, not by meaning.** A section of the other
  form is answered when the outline names blocks with content; whether that
  content meets the form's intent is for a reader to judge.
- **Outlines choose and order blocks; they do not change a block's own
  layout.** A block prints the same table or list in every outline.
- Signable PDFs with signature fields, freeze manifests, and change orders
  remain planned; see the
  [roadmap](../specs/initiatives/INIT-CONSULTINGENGAGEMENTSPEC-001/ROADMAP.md).
